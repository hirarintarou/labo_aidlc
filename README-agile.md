# AI-DLC 使い方ガイド — アジャイル編

> **対象読者**: AI-DLC を初めて使う方。短いサイクルで動くものを作りながら  
> 改善を繰り返すアジャイル型の開発に適した使い方をまとめています。

---

## AI-DLC とは

AI-DLC (AI-Driven Development Life Cycle) は、AI コーディングアシスタントを  
**構造化された開発ワークフロー**に変えるフレームワークです。

- 小さく始めて、動くものをすぐに作れます
- 各ステップの終わりに **承認ゲート** があり、方向を変えたいときはそこで修正できます
- 何を決めたかが記録されるので、次のスプリントに引き継げます

---

## アジャイルに向いているスコープ

| スコープ名 | 特徴 | 向いているケース |
|---|---|---|
| `feature` | 全33ステージ・標準的な深さ | 新機能を1サイクルでしっかり作りたいとき |
| `mvp` | 運用フェーズをスキップ・素早く核心部分を出荷 | プロトタイプ・最初のリリース |
| `express` | 最軽量・要件→コード→テスト→デプロイのみ | 小さな変更・素早い検証 |

アジャイルでは **「今回のスプリントで何を作るか」** に合わせてスコープを選べます。

---

## スコープの選び方

```
今回の作業はどれ？
  ↓
  ├── 新機能を最初から最後まで作る → feature
  ├── まず動くものを出して検証したい → mvp
  ├── 小さな修正・素早く試したい → express
  ├── バグを直す → bugfix
  └── リファクタリング → refactor
```

## 始め方（ステップバイステップ）

### ステップ 1: Kiro IDE を開く

このプロジェクトフォルダを Kiro IDE で開きます。  
AI-DLC は自動的に有効になっています（設定済み）。

### ステップ 2: モデルを確認する

Kiro IDE のチャットモデルを **Claude Opus 4.8** に設定します。  
AI-DLC は高度な推論モデルで最もよく動作します。

### ステップ 3: セットアップを確認する

チャットに以下のコマンドを入力して、問題がないか確認します:

```
/aidlc --doctor
```

「PASS」または「ok」が並んでいれば準備完了です。

### ステップ 4: 今回のスプリントの作業を伝える

作りたいものをシンプルに説明します。スコープを指定するか、AI-DLC に自動判別させます:

```
/aidlc --scope mvp ユーザーが商品を検索できる機能を作りたい
```

```
/aidlc --scope express ログインのバリデーションエラーメッセージを改善したい
```

```
/aidlc --scope feature 注文管理ダッシュボードを作りたい
```

スコープを指定しなければ、AI-DLC が説明からスコープを自動で選びます:

```
/aidlc ショッピングカートに割引コードを適用する機能を追加したい
```

### ステップ 5: 承認ゲートで確認・方向調整

各ステップが終わると AI-DLC は**承認ゲート**で止まります。  
ここがアジャイルの「レビュー」の場面です:

- **そのまま進む**: `y` または `1` と入力
- **今回のスプリントに合わせて絞り込む**: 「この機能は今回は不要です」と伝える
- **方向を変える**: フィードバックをテキストで伝えて修正してもらう

### ステップ 6: 次のスプリントへ繋げる

ひとつの `intent`（スプリントの作業単位）が完了したら、次の機能を新しい `intent` として始めます:

```
/aidlc --scope feature 次のスプリント: 支払い方法の追加
```

## スコープ別の典型的な流れ

### mvp スコープ（プロトタイプ・最初のリリース）

```
/aidlc --scope mvp <説明>
         ↓
  [初期化]
         ↓
  [アイデア出し（簡略版）]
    • スコープ定義 → フィージビリティ → 大まかなモックアップ ← 承認ゲート
         ↓
  [立ち上げ]
    • 要件分析 → 設計 → コード生成計画              ← 承認ゲート
         ↓
  [構築]
    • コード生成 → ビルド・テスト                   ← 承認ゲート
         ↓
      完了！（運用フェーズはスキップ）
      → 検証後は feature スコープで本番対応へ
```

### express スコープ（小さな変更・素早い検証）

```
/aidlc --scope express <説明>
         ↓
  [初期化]
         ↓
  [要件分析]                                        ← 承認ゲート
         ↓
  [コード生成] → [ビルド・テスト]                   ← 承認ゲート
         ↓
  [デプロイ（条件付き）]
         ↓
      完了！（最速コース）
```

### feature スコープ（新機能をしっかり作る）

```
/aidlc --scope feature <説明>
         ↓
  [全33ステージ実行]
  アイデア出し → 立ち上げ → 構築 → 運用
  （各フェーズの終わりに承認ゲート）
         ↓
      完了！
```

## アジャイル運用のコツ

### 1 スプリント = 1 intent

AI-DLC は1つの作業を「intent（意図）」という単位で管理します。  
スプリントの作業単位と intent を対応させると管理しやすくなります。

```
スプリント1 → /aidlc --scope mvp ユーザー登録機能
スプリント2 → /aidlc --scope feature ダッシュボード機能
スプリント3 → /aidlc --scope express パフォーマンス改善
```

### 承認ゲートをスプリントレビューとして活用する

承認ゲートが出たタイミングで、チームメンバーにレビューしてもらいましょう。  
AI が作成した成果物に対してフィードバックを伝えるだけで、次のステップに反映されます。

### 「学習」を次のスプリントに活かす

AI-DLC はワークフロー中に気づいたことを「学習」として記録できます。  
次回以降のワークフローで自動的に考慮されるようになります。

## 便利なコマンド

| コマンド | 説明 |
|---|---|
| `/aidlc --doctor` | セットアップの確認 |
| `/aidlc --status` | 現在の進捗を確認 |
| `/aidlc --scope mvp <説明>` | MVP スコープで開始 |
| `/aidlc --scope express <説明>` | Express スコープで開始（最速） |
| `/aidlc --scope feature <説明>` | Feature スコープで開始 |
| `/aidlc --scope bugfix <説明>` | バグ修正スコープで開始 |
| `/aidlc --scope refactor <説明>` | リファクタリングスコープで開始 |
| `/aidlc compose "<作業説明>"` | AI にカスタムワークフローを提案させる |
| `/aidlc --stage <ステージ名>` | 特定のステージにジャンプ |
| `/aidlc --version` | バージョン確認 |
| `aidlc-session-cost` | 今のセッションの統計を表示 |
| `aidlc-replay` | 作業履歴を表示 |
| `aidlc-outcomes-pack` | 成果物まとめ (OUTCOMES.md) を生成 |

## よくある質問

**Q. スコープを間違えて始めてしまったら？**  
A. 承認ゲートで止まっているときに「`express` スコープに変更して進めてください」と  
チャットで伝えることができます。AI-DLC は柔軟に対応します。

**Q. 前のスプリントの作業を参照したい。**  
A. `aidlc/spaces/default/intents/` 以下に各スプリントの成果物が保存されています。  
`aidlc-replay` コマンドでその概要を確認できます。

**Q. MVP が完成したら次に何をすればいい？**  
A. `feature` または `enterprise` スコープで新しい intent を始めます。  
前回の成果物はそのまま残っているので、AI-DLC が文脈を引き継ぎます。

**Q. チームで使うには？**  
A. `aidlc/` フォルダを Git にコミットすると、チーム全員が同じ作業記録を共有できます。  
各メンバーがそれぞれ Kiro IDE でプロジェクトを開けば、続きから作業できます。

## トラブルシューティング

| 症状 | 対処法 |
|---|---|
| `aidlc` コマンドが見つからない | PowerShell を再起動するか `$env:Path = 'C:\Users\User\AppData\Local\aidlc\bin;' + $env:Path` を実行 |
| `/aidlc --doctor` でエラーが出る | エラー内容を確認し、表示された手順に従って修正 |
| どのスコープを選べばいいかわからない | `/aidlc compose "<作業説明>"` で AI に提案させる |
| ワークフローが進まない | `/aidlc --status` で現在地を確認し、チャットで続きを指示 |
