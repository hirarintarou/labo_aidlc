# Performance Requirements — screenshot-editor（mvp）

要件 NFR6（応答性）を、mvpに比例した受け入れ可能な目標に落とす。対象は一般的なPNG/JPEG（フルHD〜4K程度）[requirements][constraint-register]。

## Performance Targets

| ID | 指標 | 目標 | 根拠/検証 |
|----|------|------|----------|
| PERF-1 | 単体編集の調整反映（プレビュー） | 一般的な画像で、スライダー操作から見た目の更新まで概ね即時（目安 ≤300ms） | NFR6。プレビューは縮小表示で計算量を抑える |
| PERF-2 | 画像を開く | 一般的な画像で概ね1秒以内に表示 | 体感的な待ちを避ける |
| PERF-3 | 単体の保存 | 一般的な画像で概ね1秒以内 | 非破壊書き出し（一時ファイル→リネーム）込み |
| PERF-4 | バッチ処理 | 1枚あたりの処理が単体保存と同等。全体は枚数に比例。実行中は進捗表示で無反応を避ける（AC2.1.4） | 直列処理で可。大量枚数時のUIフリーズ回避（処理は別スレッド/非同期で） |

## Approach Notes

- プレビューは表示解像度に合わせた縮小画像で計算し、保存時のみ原寸で適用することで応答性を確保（PERF-1）。
- バッチ・保存など時間のかかる処理はUIスレッドをブロックしない（進捗更新・キャンセル不可でも無反応にしない）。
- 高解像度（4K超）や大量枚数は mvp の主対象外だが、クラッシュはしない（NFR1）。

## Out of Scope（mvp性能）

- 厳密なベンチマーク基準・SLA。数値目標は「体感的に実用的」を基準とし、正式な性能試験は行わない（個人利用・mvp）。

## Assumptions & Open Questions

- 上記目標値は目安。実測に基づく最適化はコード生成後に必要に応じて行う。
