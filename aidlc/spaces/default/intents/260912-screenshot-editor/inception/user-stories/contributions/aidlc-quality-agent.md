## Contribution

品質エンジニアとして、各受け入れ基準（AC）が「明確な合否判定が可能か（inception ルール）」の観点で独立レビューした。solo mvp なので過剰な網羅は求めず、P0 不変条件（非破壊保存＝元バイト不変、PNG/JPEG ラウンドトリップ）に判定可能性が集中しているかを重点確認した。

### 1. P0 不変条件は概ね捕捉されているが、ラウンドトリップ精度が AC 化されていない

- 非破壊保存の不変条件は AC1.7.2（元画像のバイト列が不変）で明確な合否判定が可能。良い。ただし team-practices の Testing Posture は「バイト列**および mtime** が不変」を P0 の検証対象としている。**AC1.7.2 に「元画像の更新時刻（mtime）も変化しない」を明記**するか、別 AC として追加を提案する（観測可能・自動検証可能）。
- 中途半端出力の禁止 AC1.7.4 は「途中失敗で中途半端な出力ファイルは残らない」だが、「失敗」の発火条件がテストから制御しづらく再現性が曖昧。**「保存の書き込み中に I/O 失敗が発生した場合、出力先に部分ファイルや一時ファイルが残らない（一時ファイル→リネーム方式）」と Given を具体化**すると、失敗注入で合否判定できる。
- PNG/JPEG **ラウンドトリップの精度**は AC 化されていない。AC1.7.3 は「出力形式が同じ」だけで、画素の保存品質を保証しない。team-practices は「PNG は画素完全一致、JPEG は寸法・チャンネル・許容誤差内、PNG↔JPEG クロス各 1 ケース」を P0 と定めている。**恒等（無加工）保存に対するラウンドトリップ AC を US1.7 に追加**することを提案する:
  - 例 AC1.7.5 Given 無加工の PNG 画像, When 保存する, Then 出力 PNG は入力と画素完全一致（幅・高さ・チャンネル・各画素値が一致）。[FR7.3][NFR3]
  - 例 AC1.7.6 Given 無加工の JPEG 画像, When 保存する, Then 出力 JPEG は寸法・チャンネル数が一致し、画素差が許容誤差内（許容基準はスタック確定時に定義）。[FR7.3]

### 2. 「プレビューに反映される」系 AC は観測可能な合否判定が弱い

- AC1.2.1〜1.2.3、AC1.3.1〜1.3.3、AC1.4.1、AC1.6.1 は Then が「プレビューにリアルタイム反映される／反映される」で、**何をもって合格とするかが観測不能**。GUI 描画の目視確認になりやすく、test-after・中核ロジック 80% カバレッジの方針（core を純粋関数として検証）と噛み合わない。
- 提案: **core（画像変換ロジック）の出力で判定できる Then に言い換える**。例:
  - AC1.2.1（明るさ）: 「明るさ +N を適用すると、全画素の輝度が単調に増加する（クリップ考慮）／恒等値（0）では入力と一致する」。
  - AC1.3.1（シャープ化）/AC1.3.2（ぼかし）: 「恒等パラメータでは入力と一致し、適用時に既知の参照画像に対し期待どおり変換される」。
  - AC1.4.1（プリセット）: 「同一入力・同一プリセットは決定的に同一出力を返す（再現性）」。
  - こうすると core を単体テストで合否判定でき、「プレビュー反映」は別途 UI 配線の最小 E2E（1〜2 本）に委ねられる。

### 3. トリミング／リサイズは観測可能な寸法 AC があり良好だが恒等・境界が不足

- AC1.5.1（指定範囲に切り抜かれる）、AC1.5.2（指定寸法になる）は寸法という観測可能な合否があり、判定可能で良い。
- ただし team-practices が P0 として挙げる境界（1px、極端なサイズ、アルファ有無）が AC に無い。solo mvp の比例配分として、最低限 **リサイズの恒等（同一寸法指定で画素不変）と 1px 等の境界 1 ケース**を AC もしくは注記で残すことを提案する。

### 4. 欠落している異常系／エッジ AC

- 開く経路の異常系は AC1.1.2（破損／非対応／0 バイト）で捕捉済み。良い。
- バッチは AC2.1.2（失敗スキップ・続行）、AC2.1.3（成功 n 件／失敗 m 件表示）で件数が観測可能。良い。ただし **「n + m = 対象総数」であること、および全件失敗（成功 0 件）でもクラッシュせず結果表示する**という不変条件が判定基準として未明記。AC2.1.3 に「表示件数の合計は対象ファイル総数と一致する」を追記すると合否が締まる。
- 保存経路の異常系（保存先が書き込み不可・ディスク不足）が US1.7 に無い。mvp・solo の比例として必須化までは求めないが、少なくとも AC1.7.4 の Given をディスク I/O 失敗として具体化すれば 1 ケースで担保できる。

### 5. トレーサビリティ観点

- 各 AC の [FR]／[NFR] 参照は概ね揃っている。追加提案の AC1.7.5/1.7.6 は [FR7.3][NFR3] に紐づく。US1.2〜1.4 の Then 言い換えは FR 参照を変えずに合否可能性のみを上げる修正であり、trace チェーンを壊さない。

全体として、ストーリー分割と INVEST の粒度は solo mvp に対して過不足なく妥当。修正は「Then を観測可能な core 出力へ寄せる」ことと「P0 ラウンドトリップ／mtime 不変を AC として明示する」ことに集中しており、テスト方針（P0 重点・core 80%・フックでローカル強制）と整合する。
