## Contribution

UX/ペルソナ観点でドラフト（stories.md / personas.md）を、確定済みUX（プレビュー中心・リアルタイム反映・文字/ボタン大きめ、rough-mockups の画面1〜3）と照らして独立レビューした。全体として要件と整合し、INVEST も守れている。以下は「まず使える」solo mvp に対して比例的な、実際に効くUXギャップのみを挙げる（過剰装飾は避ける）。

### 1. リセット／やり直しのストーリーが無い（確定UXとの不整合・要追加）

wireframes.md 画面1の右調整パネルには **[ リセット ]** ボタンが明示されている。加えてペルソナP1のゴール「多くの加工を試して感性に合う一枚を作りたい」は、**試す→戻す**の往復が前提であり、UX上のコア動作である。しかし stories.md にはリセット／やり直しに触れるストーリー・ACが一つも無い。ux-guide のヒューリスティック3「User control and freedom（取り消し・戻る）」に照らしても欠落。

提案（新規ストーリー、Must 相当。US1.2〜1.6 に共通する横断ACとして US1.8 を新設するのが素直）:

- US1.8 調整をリセットして試し直す — Must
  - As a P1, I want 適用中の調整値を初期状態に戻したい, so that 気に入らなければ元に戻して別の仕上がりを試せる。
  - AC1.8.1 Given いずれかの調整を変更した状態, When 「リセット」を押す, Then 全調整値が初期値に戻り、プレビューが未加工（開いた直後）の表示に戻る。[FR8.1][rough-mockups]
  - AC1.8.2 Given リセット, When 実行する, Then 元画像ファイルには一切変更が及ばない（非破壊が保たれる）。[NFR3]

補足: solo mvp なので多段Undo（Ctrl+Z履歴）まで要求しない。ワイヤーにある「全体リセット」で十分。ここは gold-plating を避け、確定済みの1ボタンに閉じることを推奨する。

### 2. 加工前／後の比較（before/after）— 有用なUXギャップ（Should 提案）

「手作業では難しい品質を手軽に得たい」「感性に合う一枚を作りたい」というP1ゴールに対し、**加工前の元画像と現在のプレビューを見比べる**手段はプレビュー中心UIの価値を大きく高める。現状ストーリーには無い。solo mvp では「押している間だけ元画像を表示（比較ボタン長押し／トグル）」程度が費用対効果が高い。

提案（US1.9、Should。mvp必須には含めず最初の目安からも外す）:

- US1.9 加工前と比較する — Should
  - AC1.9.1 Given 調整を加えた状態, When 比較操作（ボタン長押しまたはトグル）を行う, Then プレビューが一時的に未加工の元画像を表示し、離す/解除で加工後に戻る。[FR8.1]

これは refined-mockups で採否を確定する候補として明示しておくのがよい（実装容易・UX効果大）。

### 3. バッチ実行中のフィードバックが弱い（要ACの補強）

US2.1 は結果表示（AC2.1.3「成功n件／失敗m件」）まではあるが、**実行中の進捗フィードバック**が無い。wireframes 画面3は「対象: 12枚」を提示しており、複数枚処理では visibility of system status（ux-guide ヒューリスティック1）が特に重要。無反応時間はP1に「固まった？」という不安を与える。solo mvp でも「n枚中m枚処理中」程度の最小進捗は妥当。

提案（AC追加）:

- AC2.1.4 Given 一括適用を開始した状態, When 処理が進行している, Then 進捗（例「12枚中5枚処理中…」）が表示され、完了まで画面が無反応に見えない。[FR9.3][NFR6]

（キャンセル可否は判断が要る。長時間バッチのキャンセルは有用だが、mvpで複雑化するなら Open Question として残す提案に留める。）

### 4. レイアウト操作＝「左メニュー選択→右パネル切替」の対話がストーリー化されていない

FR8.2／wireframes 画面1で「左の加工メニューでカテゴリを選ぶと右パネルに該当スライダーが出る」という中核ナビゲーションが確定している。US1.1〜1.7 は各加工の効果には触れるが、この**カテゴリ選択→調整パネル切替**という画面の骨格操作を受け入れ可能な形で拾っていない。テスト可能なACとして US1.1 か新設の「画面レイアウト」ストーリーに1行加えると、開発・QAの受け入れ基準が明確になる。

提案（US1.1 への追加、または軽量な横断AC）:

- AC1.1.3 Given 画像を開いた状態, When 左メニューのカテゴリ（基本補正/画質/フィルタ/トリミング/リサイズ/クレジット）を選ぶ, Then 右の調整パネルが該当カテゴリの操作に切り替わる。[FR8.2][rough-mockups]

### 5. アクセシビリティ／可読性（NFR4）を担保するテスト可能なACが不在

NFR4「文字・ボタン大きめ／見やすいUI」と wireframes のアクセシビリティ注記（landmark、キーボード起点=左メニュー、Escでモーダル閉）は確定済みだが、ストーリー側にこれを検証する足がかりが無い。solo mvp なので網羅的WCAG監査は求めない。最低限「キーボードで主要動線（開く→調整→保存）を通せる」「モーダルはEscで閉じる」だけ受け入れ可能な形にしておくと、後段で崩れにくい。

提案（横断的な受け入れ条件、または US1.1／US2.1 へ薄く付与）:

- AC（例）Given メイン画面, When マウスを使わずキーボードのみで操作する, Then 「開く→カテゴリ選択→調整→保存」の主要動線を完了でき、フォーカス位置が視認できる。[NFR4][rough-mockups]
- AC（例）Given バッチ適用ダイアログ, When Esc キーを押す, Then ダイアログが閉じ、フォーカストが起動元に戻る。[rough-mockups]

（full WCAG 2.1 AA 準拠の確証には支援技術での手動検証と専門レビューが必要なため、ここでは主要動線の keyboard operability と Esc 閉じるに絞るのが比例的。）

### ペルソナ忠実性

personas.md のP1は intent／requirements と一致し、ゴール・ペインポイント・利用文脈（Windows・ローカル・非破壊）とも矛盾しない。単一ペルソナはQ1回答（A）とも整合。忠実性に問題なし。1点だけ、P1ゴールの「多くの加工を試す」が上記1・2（リセット／比較）のUX根拠になっている旨をストーリー側の trace として拾えると、ペルソナ→ストーリーの追跡性が上がる（必須ではない）。

### 過剰装飾として意図的に「提案しなかった」もの

- 多段Undo/Redo履歴（ワイヤーの全体リセットで足りる。mvpにはオーバースペック）。
- プリセットのサムネイル一覧プレビュー（refined-mockups の検討事項に委ねる。ここで縛らない）。
- レスポンシブ／モバイル対応（Windowsデスクトップ専用・単一ウィンドウのため対象外）。

## Positions

- AGREE: ワークフロー2グループ分割（US1/US2）、機能ごとの細粒度ストーリー、リアルタイム反映AC、非破壊保存の一連AC（AC1.7.1〜1.7.4）、バッチのスキップ継続・件数表示は、確定UX・ペルソナ・要件と整合しており支持する。
- OBJECT: リセット／やり直しのストーリーが欠落している点（上記1）。wireframes 画面1に明示された [ リセット ] とP1ゴール「試して戻す」に対する明確な不整合であり、US1.8（AC1.8.1／AC1.8.2）の追加を求める。
