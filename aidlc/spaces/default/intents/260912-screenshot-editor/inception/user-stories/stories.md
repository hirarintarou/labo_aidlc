# User Stories — FF14 スクリーンショット加工ツール（mvp）

ワークフローごとに2グループ（US1: 1枚を仕上げる流れ、US2: 複数枚を処理する流れ）に加え、
確定プラクティス（skeleton: on）に対応する縦断スライスの技術ストーリー US0 を先頭に置く [team-practices]。
各加工機能は個別ストーリーとして細かく定義する [Q2][Q3]。優先度は MoSCoW。
ペルソナはすべて P1（制作者本人）。受け入れ基準は、中核ロジック（core）で観測・検証できる形を優先する [team-practices]。

---

## US0. 骨組み（縦断スライス）

### US0.1 開く→無加工→非破壊保存を端から端まで通す — Must
As a P1（制作者本人）, I want 画像を開いて無加工のまま非破壊保存できる最小の骨組みを最初に通したい, so that 各部品（ui→core→io）が実際につながることを確かめてから機能を積める。
- AC0.1.1 Given PNG/JPEG画像, When 開いて（無加工で）保存する, Then ui→core→io を貫通して元と同じフォルダに接尾辞付きの別ファイルが出力される。[FR1.1][FR7.1][FR7.2]
- AC0.1.2 Given 無加工のPNG画像, When 保存する, Then 出力PNGは入力と画素完全一致（幅・高さ・チャンネル・各画素値が一致）。[FR7.3][NFR3]
- AC0.1.3 Given 無加工のJPEG画像, When 保存する, Then 出力JPEGは寸法・チャンネル数が一致し、画素差が許容誤差内（許容基準はスタック確定時に定義）。[FR7.3]
- AC0.1.4 Given 保存後, When 元画像を確認する, Then 元画像のバイト列および更新時刻(mtime)が不変。[NFR3]
- INVEST: 最初のBoltで実装。E2E最小疎通テストとラウンドトリップテストを骨組みと共用する [team-practices]。

## US1. 1枚を仕上げる流れ（単体プレビュー編集）

### US1.1 画像を開いてプレビュー表示する — Must
As a P1, I want ローカルのPNG/JPEG画像を開いてプレビュー表示したい, so that 加工の対象を画面で確認しながら作業できる。
- AC1.1.1 Given PNG または JPEG のファイル, When それを開く, Then 中央のプレビュー領域に画像が表示される。[FR1.1][FR1.2]
- AC1.1.2 Given 壊れた/非対応/0バイトのファイル, When それを開こうとする, Then 「このファイルは開けませんでした（対応形式は PNG / JPEG です）」等の日本語メッセージが表示され、アプリはクラッシュしない。[FR1.3][NFR1]
- AC1.1.3 Given 画像を開いた状態, When 左メニューのカテゴリ（基本補正/画質/フィルタ/トリミング/リサイズ/クレジット）を選ぶ, Then 右の調整パネルが該当カテゴリの操作に切り替わる。[FR8.2]

### US1.2 基本補正を行う — Must
As a P1, I want 明るさ・コントラスト・彩度を調整したい, so that 画像の見栄えを整えられる。
- AC1.2.1 Given 画像, When 明るさ +N を core に適用する, Then 恒等値(0)では入力と一致し、正の値では全画素の輝度が単調に増加する（クリップ考慮）。プレビューにもリアルタイム反映される。[FR2.1][FR2.4]
- AC1.2.2 Given 画像, When コントラストを変更する, Then 恒等値では入力と一致し、変更時に core が決定的な出力を返す。プレビューにリアルタイム反映される。[FR2.2][FR2.4]
- AC1.2.3 Given 画像, When 彩度を変更する, Then 恒等値では入力と一致し、変更時に core が決定的な出力を返す。プレビューにリアルタイム反映される。[FR2.3][FR2.4]

### US1.3 画質を調整する — Must
As a P1, I want シャープ化・ぼかし・ノイズ除去を適用したい, so that 画像の精細感やなめらかさを整えられる。
- AC1.3.1 Given 画像, When シャープ化を適用する, Then core は恒等パラメータで入力と一致し、適用時に既知の参照画像へ期待どおり変換する。プレビューに反映される。[FR3.1]
- AC1.3.2 Given 画像, When ぼかしを適用する, Then core は恒等パラメータで入力と一致し、適用時に決定的な出力を返す。プレビューに反映される。[FR3.2]
- AC1.3.3 Given 画像, When ノイズ除去を適用する, Then core は決定的な出力を返す。プレビューに反映される。[FR3.3]

### US1.4 フィルタ／プリセットを適用する — Must
As a P1, I want ワンタッチで雰囲気を変えるプリセットを適用したい, so that 少ない手数で感性に合う仕上がりを試せる。
- AC1.4.1 Given 画像, When プリセットを選ぶ, Then 同一入力・同一プリセットは決定的に同一出力を返す（再現性）。プレビューに反映される。[FR4.1]
- AC1.4.2 Given mvp, When プリセット一覧を見る, Then 6〜10種類程度の代表的なプリセットが選べる。[FR4.2]

### US1.5 トリミング・リサイズを行う — Must
As a P1, I want 画像を切り抜いたりサイズ変更したい, so that 公開用に構図やサイズを整えられる。
- AC1.5.1 Given 画像, When トリミング範囲を指定して適用する, Then 出力は指定範囲の寸法に一致する。[FR5.1]
- AC1.5.2 Given 画像, When リサイズ寸法を指定して適用する, Then 出力は指定寸法に一致する（アスペクト比を保持するか否かは指定に従う）。同一寸法指定では画素が不変（恒等）。1px等の境界寸法でもクラッシュしない。[FR5.2]

### US1.6 クレジット／ウォーターマークを付与する — Must
As a P1, I want テキストのクレジットを画像に付与したい, so that 公式ガイドラインに沿った出典表記を入れられる。
- AC1.6.1 Given 画像, When クレジットテキストと位置・サイズ・不透明度を指定する, Then core が画像へテキストを合成した結果を返し、プレビューに表示される。[FR6.1][FR6.2]
- AC1.6.2 Given クレジット入力欄, When 初期状態を見る, Then 既定テンプレート（例「© SQUARE ENIX」）が入っており、編集できる。[FR6.3]
- AC1.6.3 Given クレジット機能, When 目的を確認する, Then 付与はFF14公式の画像利用ガイドライン遵守を目的とする（任意付与）。[FR6.4]

### US1.7 加工結果を非破壊で保存する — Must
As a P1, I want 加工結果を元画像を壊さずに保存したい, so that 元のスクショを失わずに公開用画像を得られる。
- AC1.7.1 Given 加工した画像, When 保存する, Then 元画像と同じフォルダに接尾辞付きの別ファイル（例 `screenshot001_edited.png`）として出力される。[FR7.1][FR7.2]
- AC1.7.2 Given 保存後, When 元画像を確認する, Then 元画像はバイト列および更新時刻(mtime)が不変。[FR7.1][NFR3]
- AC1.7.3 Given 入力がPNG（またはJPEG）, When 保存する, Then 出力も同じ形式になる。[FR7.3]
- AC1.7.4 Given 保存の書き込み中にI/O失敗が発生した場合, When 失敗する, Then 出力先に部分ファイルや一時ファイルが残らない（一時ファイル→リネーム方式）。[FR7.4]
- AC1.7.5 Given 無加工のPNG画像, When 保存する, Then 出力PNGは入力と画素完全一致。[FR7.3][NFR3]
- AC1.7.6 Given 無加工のJPEG画像, When 保存する, Then 出力JPEGは寸法・チャンネル数が一致し、画素差が許容誤差内。[FR7.3]

### US1.8 調整をリセットして試し直す — Must
As a P1, I want 適用中の調整値を初期状態に戻したい, so that 気に入らなければ元に戻して別の仕上がりを試せる。
- AC1.8.1 Given いずれかの調整を変更した状態, When 「リセット」を押す, Then 全調整値が初期値に戻り、プレビューが未加工（開いた直後）の表示に戻る。[FR8.1]
- AC1.8.2 Given リセット, When 実行する, Then 元画像ファイルには一切変更が及ばない。[NFR3]

### US1.9 加工前と比較する — Should（mvp必須外・最初の目安外）
As a P1, I want 加工前の元画像と現在のプレビューを見比べたい, so that 加工の効果を確認して感性に合う一枚を選べる。
- AC1.9.1 Given 調整を加えた状態, When 比較操作（ボタン長押しまたはトグル）を行う, Then プレビューが一時的に未加工の元画像を表示し、解除で加工後に戻る。[FR8.1]
- 備考: refined-mockups で採否・詳細を確定する候補。

## US2. 複数枚を処理する流れ（バッチ）

### US2.1 同じ設定で複数枚に一括適用する — Must
As a P1, I want 1枚で決めた加工設定を複数枚にまとめて適用したい, so that 公開画像が増えても手作業に追われずに済む。
- AC2.1.1 Given 1枚で加工設定を決めた状態, When フォルダまたは複数ファイルを選んで一括適用する, Then 各画像に同じ設定が適用され、非破壊で保存される。[FR9.1][FR9.2]
- AC2.1.2 Given バッチ対象に壊れた/非対応ファイルが混ざっている, When 一括適用する, Then その失敗ファイルはスキップされ残りは続行される。全件失敗（成功0件）でもクラッシュしない。[FR9.3][NFR1]
- AC2.1.3 Given バッチ完了, When 結果を見る, Then 「成功n件／失敗m件」が表示され、n + m は対象ファイル総数に一致する。[FR9.3]
- AC2.1.4 Given 一括適用を開始した状態, When 処理が進行している, Then 進捗（例「12枚中5枚処理中…」）が表示され、完了まで画面が無反応に見えない。[FR9.3][NFR6]

## 横断的な受け入れ基準（アクセシビリティ／可読性）

- ACX.1 Given メイン画面, When マウスを使わずキーボードのみで操作する, Then 「開く→カテゴリ選択→調整→保存」の主要動線を完了でき、フォーカス位置が視認できる。[NFR4]
- ACX.2 Given バッチ適用ダイアログ, When Escキーを押す, Then ダイアログが閉じ、フォーカスが起動元に戻る。[NFR4]
- 備考: 完全なWCAG準拠の確証には支援技術での手動検証と専門レビューが必要。ここでは主要動線のキーボード操作性とEsc閉じるに絞る。

## Dependencies

- US0.1（骨組み）を最初に通す。US1.1（開く）・US1.7（保存）の疎通面を先取りする。
- US1.2〜US1.6・US1.8 は US1.1（画像を開く）に依存。
- US1.7（保存）は加工系ストーリーの後段（骨組みで疎通済み）。
- US2.1（バッチ）は US1.x（単体加工設定）に依存。加工設定を保持・再適用するための設定モデルを core 側に用意する必要があり、機能設計で確定する。
