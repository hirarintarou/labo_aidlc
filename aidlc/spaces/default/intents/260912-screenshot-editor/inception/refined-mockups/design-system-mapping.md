# Design System Mapping — FF14 スクリーンショット加工ツール（mvp）

既存のデザインシステムは持たない（個人開発・新規）[team-practices]。ここでは、選定するGUIフレームワークの標準コンポーネントに素直にマッピングする方針を示す。技術スタック未確定のため、具体的なウィジェット名はスタック確定後に確定する。

## コンポーネント対応（論理 → 標準ウィジェット）

| 論理コンポーネント | 標準ウィジェットの種類 | 備考 |
|-------------------|----------------------|------|
| ツールバー（開く/保存/バッチ） | ツールバー＋ボタン | 大きめのボタン [NFR4] |
| 加工カテゴリメニュー（左） | リスト／ナビゲーションリスト | 単一選択、キーボード移動可 |
| プレビュー領域（中央） | 画像表示ウィジェット | 拡大縮小に追従 |
| 調整パネル（右） | スライダー・ラジオ・数値入力・テキスト入力 | ラベル併記、フォーカス可視 |
| フィルタ一覧 | ラジオリスト（テキスト） | サムネイルは使わない [Q2] |
| バッチダイアログ | モーダルダイアログ＋プログレスバー | Escで閉じる |
| 通知（成功/エラー） | メッセージ表示／ステータス領域 | 日本語メッセージ |

## スタイル方針

- **文字・ボタンは大きめ**、コントラストを確保し見やすくする [NFR4]。
- 配色・タイポグラフィはOS標準（Windows）に準拠し、独自デザイントークンは最小限とする。
- アイコンは標準的なもの（開く=フォルダ、保存=ディスク等）を用い、テキストラベルを併記する。

## 対応方針の確定タイミング

- 具体的なフレームワーク（例: WPF/WinUI、PySide/Tkinter、Electron/Tauri 等）と各ウィジェットの対応は、Units Generation / Functional Design でのスタック選定後に確定する [team-practices]。

- 技術スタック未確定のため、具体的なコンポーネント名・スタイル値は保留。
