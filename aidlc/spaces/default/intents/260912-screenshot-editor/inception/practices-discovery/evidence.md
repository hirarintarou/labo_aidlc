## 参加者が確認・推論したもの

### リード（release engineer）

- 確認: `aidlc/spaces/default/memory/org.md` の 5 セクションをグリーンフィールドの
  推奨既定として参照（既定 Methodology=test-after、mvp は 80% ラインカバレッジ下限）。
  `aidlc/spaces/default/memory/team.md` を再実行ベースライン（プレースホルダ）として参照。
  `.kiro/aidlc-common/stages/inception/practices-discovery.md` で成果物の形状
  （4 つの宣言成果物、Testing Posture の構造化 2 フィールド）を確認。
- 推論: 個人開発・ローカル完結・Windows 専用・mvp のため、PR レビューはセルフ確認中心、
  デプロイはローカルビルド/インストール、テストツール等の具体名は保留、と org.md 既定を調整。
  確定済みスコープ（非破壊保存・PNG/JPEG 入出力・ローカル完結）から硬い制約を導出。

### quality-agent

- 確認/推論: Testing Posture（test-after + Ordering）は本ツールの性質に妥当と評価。
  org.md の mvp 80% 下限を **アプリ全体（GUI 含む）に一律適用すると solo では過大**と
  指摘し、コア層（画像処理・入出力・保存）に限定する測定対象スコープの切り分けを提案。
  CI ゲートは pre-commit/pre-push フックまたは単一タスクで「green＋カバレッジ下限」を
  機械的に強制することを推奨。重点テスト（非破壊保存の不変条件、PNG/JPEG ラウンド
  トリップ、単体・プロパティベース・最小 E2E）とテストデータ戦略（合成フィクスチャ）を提示。

### developer-agent

- 確認/推論: レイヤー境界（画像処理コアを UI から分離、依存方向 ui → core → io）が
  team-practices に未明文化と指摘し、mvp でも固定すべき原則として提案。破損画像・
  非対応フォーマット時のエラー処理原則（早期検証・ユーザー向け日本語メッセージ変換・
  クラッシュ回避・一時ファイル→リネームのアトミック書き出し）を提案。ファイルは機能/
  責務単位でまとめる構造の一貫性を推奨。フォーマッタ/リンタ・ライブラリ具体名は保留。

### devsecops-agent

- 確認/推論: ネットワーク I/O が無い本ツールで実質的な攻撃面は **サプライチェーンと
  画像パーサ** の 2 点と分析。依存のバージョン固定＋ロックファイルのコミット、未検証
  画像の標準 API による安全なデコード、リンタのセキュリティルール有効化を採用推奨。
  DAST/重量級 SAST/認証認可/暗号化/コンテナ・IaC スキャン/常設 SBOM はスコープ過剰として不採用。

## インタビューでの人間の決定（Q1〜Q8）

- Q1=A: 1 リポジトリ・作業ブランチ→main、形式的 PR レビュー省略・セルフ確認。
- Q2=B: **ウォーキングスケルトンを作る（skeleton ON）**。ドラフトの「作らない(off)」を
  上書き。「画像を開く→加工→非破壊保存」が端から端まで通る最小の骨組みを先に用意する。
- Q3=A: test-after。中核（画像処理・入出力・保存）を手厚くテスト。
- Q4=A: 80% カバレッジ下限を中核ロジック層（補正・フィルタ・入出力・保存）に限定して
  適用し、GUI/配線層は対象外。org.md の mvp 80% 下限を測定対象スコープに特化して team.md に明記。
- Q5=A: pre-commit/pre-push フック等で「テスト green＋カバレッジ下限」をローカルで
  機械的に強制。リモート CI は必須としない。
- Q6=A: デプロイ=ローカルビルド/インストール。サーバー・CD パイプライン・本番承認ゲートは適用外。
- Q7=A: コード構造・エラー処理の 3 原則を全部採用（core は UI 非依存 ui→core→io、破損/
  非対応入力を早期検証し日本語メッセージへ変換しクラッシュしない、保存は一時ファイル→
  リネーム等で安全に元画像を壊さない）。
- Q8=A: 依存はバージョン固定＋ロックファイルをコミット（タイポスクワッティング注意）、
  読み込む画像は未検証データとして標準ライブラリで安全に扱う。両方採用。
- Consolidated Summary: Looks correct。

- テストランナー・カバレッジツール・フォーマッタ・リンタ・pre-commit/pre-push フックの具体名
  （スタック確定後に確定）。
- JPEG ラウンドトリップの許容誤差基準、非破壊保存の出力先・命名規則、型付きエラーの実現手段。

  カバレッジ測定対象スコープ）はスタック非依存で確定済みである。
