# Discovered Rules

> 本プロジェクトで確立していると判断できる硬い制約のみを記載する。確定済みスコープ・
> 非破壊保存・ローカル完結の要件に加え、インタビュー（Q7/Q8）と developer/devsecops
> レビューの合意を統合して確定した。

## Mandated

- ALWAYS 画像処理をローカル・オフラインで完結させる（外部サーバーへ画像やデータを
  送信しない）。
- ALWAYS 元画像を保持したまま非破壊で保存する（加工結果は別ファイルとして出力する）。
- ALWAYS git のコミットメッセージを日本語で記述する（ワークスペースのコミット
  メッセージ規約に従う）。
- ALWAYS PNG および JPEG の入出力をサポートする。
- ALWAYS 画像処理コアを UI から分離する（core は GUI に依存しない。依存方向は
  ui → core → io の一方向とし、コアは GUI を import しない）。
- ALWAYS 壊れた/非対応の入力を入力境界で早期に検証し、クラッシュさせず、ユーザー
  向けの日本語メッセージに変換する（fail fast）。
- ALWAYS 依存ライブラリを正確なバージョンで固定（ピン留め）し、ロックファイルを
  リポジトリにコミットする（導入時に類似名／タイポスクワッティングを目視確認する）。
- ALWAYS 読み込む画像を未検証データとして扱い、標準ライブラリ/選定ライブラリの
  API で安全にデコードする（独自パーサを書かない）。
- ALWAYS 保存は元画像を壊さず安全に書き出す（出力先の書き込み可否を検証し、可能なら
  一時ファイル → リネームのアトミック書き出しで中途半端な出力を残さない）。

## Forbidden

- NEVER 元画像ファイルを上書き・破壊する。
- NEVER 画像やユーザーデータを外部ネットワーク・第三者サービスへ送信する。

## Assumptions & Open Questions

- 上記は確定済みスコープ・非破壊保存・ローカル完結の要件、および Q7/Q8 の合意から
  導いた硬い制約である。
- 保存先の既定・ファイル命名規則、型付きエラーの実現手段（例外型/結果型）、画像処理
  ライブラリの具体名は、技術スタック確定後に後続ステージで確定する。
