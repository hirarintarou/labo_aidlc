# Intent Backlog — FF14 スクリーンショット加工ツール（mvp）

優先度は MoSCoW で分類する。Must = mvp必須、Should/Could = 将来（mvp外）。
proto-Unit は後続の Units Generation で正式なユニットに整理する暫定の作業のかたまり。

|----|------------------------------|--------|------|------|--------|
| B-1 | 画像の読み込み・非破壊保存の基盤（PNG/JPEG、別ファイル出力） | Must | 全機能の前提 | 最初に必要な土台 | [constraint-register][Q3] |

## MVP Boundary

- **Must（B-1〜B-8）** がmvpの実装対象。
- **Should/Could（B-9, B-10）** はmvp外（将来バージョン）。
- 実装順序の希望はなし（おまかせ）。基盤 B-1 を最初に、UI基盤 B-7 と各加工機能を段階的に、バッチ B-8 は加工機能が揃った段階で、という並びを想定（正式な順序は delivery-planning で確定）[Q5]。

## Value Stream（capability → outcome）

- B-1〜B-6（各加工能力）→ 手作業では難しい品質を手軽に得る／多彩な加工を試して感性に合う一枚を作る [intent-statement]
- B-7（プレビュー編集）→ 1枚ずつ納得いくまで仕上げる [Q4]
- B-8（バッチ）→ 公開画像が増えても手作業に追われない [intent-statement]
